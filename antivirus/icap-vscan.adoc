= 온액세스 스캐닝을 위해 ICAP 기반 ONTAP Vscan을 구성합니다.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ONTAP 9.20.1부터는 ONTAP Antivirus Connector를 설치하지 않고도 ICAP(Internet Content Adaptation Protocol) 기반 Vscan을 구성하여 액세스 시 바이러스 백신 검사 요청을 ICAP 지원 검사 엔진으로 직접 전송할 수 있습니다. ICAP 기반 Vscan은 기존 FPolicy 공유 메모리 알림 인프라를 사용하여 연결을 관리하고 검사 요청을 전달합니다.

ICAP 기반 Vscan은 표준 ICAP REQMOD 또는 RESPMOD 메서드 대신 FILEMOD(파일 수정 요청)라는 독자적인 ICAP 확장 기능을 사용합니다:

* *경로 기반 스캔*: ONTAP은 ICAP 요청 헤더에 파일 경로와 메타데이터만 전송합니다. 네트워크를 통해 스캔 엔진으로 파일 콘텐츠를 스트리밍하지 않습니다.
* *직접 파일 액세스*: 스캔 엔진은 관련 ONTAP 공유를 마운트하고 구성된 권한 있는 사용자 계정을 사용하여 SMB 프로토콜을 통해 파일 데이터를 직접 읽습니다.
* *장점*: 이 접근 방식은 대용량 파일 스트리밍 시 발생하는 CPU 및 메모리 오버헤드를 방지하고, 네트워크 트래픽을 줄이며, 바이러스 백신 커넥터에서 사용하는 효율적인 읽기 경로를 유지합니다.




[[supported-scan-engines]]
== 지원되는 스캔 엔진

다음과 같은 ICAP 지원 스캔 엔진이 지원됩니다:

* Symantec Protection Engine (SPE)
* OPSWAT MetaDefender




[[configuration-considerations]]
== 구성 고려 사항

ICAP 기반 Vscan을 구성할 때 다음 사항을 유념하십시오:

* 각 SVM은 ICAP 기반 Vscan 구성 또는 Antivirus Connector 스캐너 풀 중 하나만 사용해야 하며, 동일한 SVM에 둘 다 구성할 수 없습니다. 둘 사이를 전환하려면 기존 구성을 먼저 제거해야 합니다.
* ICAP 기반 Vscan은 SMB에 대해서만 액세스 시 스캔을 지원합니다. 온디맨드 스캔 및 NFS 액세스 시 스캔은 지원되지 않습니다.
* ONTAP 9.20.1에서 이전 버전으로 되돌리기 전에 ICAP 기반 Vscan 구성을 모두 제거하십시오.


.시작하기 전에
* 클러스터는 ONTAP 9.20.1 이상 버전을 실행해야 합니다.
* SVM에는 SMB가 구성되고 활성화되어 있어야 합니다.
* 클러스터 네트워크에서 접근 가능한 서버에 ICAP를 지원하는 바이러스 백신 검사 엔진(SPE 또는 OPSWAT 등)이 설치되어 실행 중이어야 합니다.
* SVM에는 기존 바이러스 백신 커넥터 구성이 없어야 합니다. 각 SVM은 ICAP 기반 Vscan 또는 바이러스 백신 커넥터 중 하나만 지원하며, 둘 다 지원할 수는 없습니다.
* ICAP 연결에 TLS 암호화가 필요한 경우 클러스터에 적절한 서버 CA 인증서를 설치하십시오.


.단계
. SVM용 ICAP 구성을 생성합니다. SVM당 하나의 ICAP 구성만 지원됩니다:
+
`vserver vscan icap-config create -vserver <svm_name> -server-ip <icap_server_ip> -port <port> -max-connections <max_conn> -service-path <service_path> -ssl-enabled {true|false} -skip-cert-validation {true|false}`

+
.예:
`cluster1::> vserver vscan icap-config create -vserver vs1 -server-ip 10.10.10.1 -port 1344 -max-connections 10 -service-path SYMCSCANRESPEX-AV -ssl-enabled false -skip-cert-validation false`

+
[cols="25,20,15,40"]
|===


| 매개 변수 | 기본값 | 범위 | 설명 


 a| 
``포트’’
| 1344 | 1–65535 | ICAP 스캔 엔진의 TCP 포트 


 a| 
`-max-connections`
| 10 | 1–256 | ICAP 서버에 대한 최대 동시 연결 수 


 a| 
`-service-path`
| SYMCSCANRESPEX-AV | 해당 없음 | 스캔 엔진에서 노출되는 ICAP 서비스 경로 


 a| 
`-ssl-enabled`
| 거짓 | 해당 없음 | ICAP 연결에 대한 TLS 암호화를 활성화합니다. 


 a| 
`-skip-cert-validation`
| 거짓 | 해당 없음 | 서버 인증서 유효성 검사 건너뛰기 
|===
. 온액세스 정책이 아직 없는 경우 해당 정책을 생성하십시오.
+
`vserver vscan on-access-policy create -vserver <svm_name> -policy-name <policy_name> -protocol CIFS -max-file-size <size> -filters <filter_list> -file-ext-to-exclude <extensions> -paths-to-exclude <paths>`

+

NOTE: 이전 Vscan 구성의 온액세스 정책이 이미 존재하고 워크로드에 적합한 경우, ICAP 경로와 함께 재사용할 수 있습니다.

. Vscan이 파일 작업을 가로채고 스캔 요청을 ICAP 서버로 라우팅하기 시작하도록 활성화하십시오.
+
`vserver vscan enable -vserver <svm_name>`

. ICAP 연결 상태를 확인하십시오:
`vserver vscan icap-connection-status show -vserver <svm_name>`
